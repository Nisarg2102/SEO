# Database Schema (MVP Phase 1)

This document describes the initial PostgreSQL database schema managed by Prisma ORM.

## Overview
The schema is designed for strict multi-tenancy. Every core operational table has a `workspace_id` foreign key referencing the `workspaces` table.

### Core Tables

#### `users`
Global users of the platform.
- `id` (UUID, PK)
- `email` (String, Unique)
- `name` (String)
- `created_at` (DateTime)
- `updated_at` (DateTime)

#### `workspaces`
Isolated organizational units.
- `id` (UUID, PK)
- `name` (String)
- `type` (String) - e.g., 'IT', 'Medical'
- `created_at` (DateTime)
- `updated_at` (DateTime)

#### `workspace_members`
Maps users to workspaces with role-based access control.
- `id` (UUID, PK)
- `workspace_id` (UUID, FK -> workspaces.id)
- `user_id` (UUID, FK -> users.id)
- `role` (String) - e.g., 'owner', 'editor', 'approver'
- `created_at` (DateTime)
- *Indexes:* `workspace_id`, `user_id`, Unique constraints on `[workspace_id, user_id]`

#### `brand_profiles`
Stores brand voice and identity per workspace.
- `id` (UUID, PK)
- `workspace_id` (UUID, FK -> workspaces.id)
- `business_name` (String)
- `description` (Text)
- `target_audience` (String)
- `location` (String)
- `tone` (String)
- `language` (String)
- `website` (String, nullable)
- `created_at`, `updated_at` (DateTime)

#### `sources`
Data sources/URLs being tracked by the AI for research.
- `id` (UUID, PK)
- `workspace_id` (UUID, FK -> workspaces.id)
- `name` (String)
- `url` (String)
- `source_type` (String) - e.g., 'competitor', 'industry_news'
- `source_tier` (String) - e.g., 'primary', 'secondary'
- `active` (Boolean)
- `created_at` (DateTime)

#### `research_items`
Individual articles/data points scraped from sources.
- `id` (UUID, PK)
- `workspace_id` (UUID, FK -> workspaces.id)
- `source_id` (UUID, FK -> sources.id)
- `title` (String)
- `url` (String)
- `summary` (Text)
- `published_at` (DateTime, nullable)
- `confidence` (Float) - AI's confidence in relevance
- `intent` (String)
- `status` (String)
- `created_at` (DateTime)

#### `content_ideas`
Actionable ideas generated by the AI based on research.
- `id` (UUID, PK)
- `workspace_id` (UUID, FK -> workspaces.id)
- `research_item_id` (UUID, nullable, FK -> research_items.id)
- `title` (String)
- `topic` (String)
- `audience` (String)
- `intent` (String)
- `status` (String) - e.g., 'pending', 'approved', 'rejected'
- `confidence` (Float)
- `created_at`, `updated_at` (DateTime)

#### `content_packs`
The final multi-platform generated content (hooks, scripts, captions).
- `id` (UUID, PK)
- `content_idea_id` (UUID, FK -> content_ideas.id)
- `platform` (String) - e.g., 'linkedin', 'twitter', 'youtube'
- `hook` (Text, nullable)
- `caption` (Text, nullable)
- `script` (Text, nullable)
- `cta` (Text, nullable)
- `hashtags` (String, nullable)
- `seo_title` (String, nullable)
- `meta_description` (Text, nullable)
- `status` (String) - e.g., 'draft', 'pending_approval', 'scheduled', 'published'
- `created_at`, `updated_at` (DateTime)

## Relations & Isolation
- `Cascade` delete is configured on workspace boundaries so deleting a workspace completely cleans up all related data.
- The schema uses standard UUIDs as primary keys to prevent enumeration attacks.
- Non-relational fields (like text, intent, and summary) strictly use primitive DB types (`String`, `Text`) instead of `JSONB` per architecture guidelines.
